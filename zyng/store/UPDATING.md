# Как выпустить обновление

Всё разовое уже сделано: приложение создано, политика опубликована, описание и
скриншоты заполнены, экспортные вопросы отвечены. Обновление — короткий цикл.

---

## 1. Подними номер сборки

В `project.yml` найди `CURRENT_PROJECT_VERSION` (он в двух местах — у приложения
и у расширения) и увеличь на единицу. Номера должны совпадать.

Apple не принимает повторно уже использованный номер сборки.

Если меняется и версия для пользователей — правь `MARKETING_VERSION`:
`1.0` → `1.1`. Для мелких правок это не обязательно, достаточно номера сборки.

## 2. Пересоздай проект и проверь

```bash
cd ~/Developer/KerimliRashad && git pull && cd zyng
rm -rf Zyng.xcodeproj && ./setup.sh && open Zyng.xcodeproj
```

Пересоздавать нужно, только если менялся `project.yml` или добавлялись файлы.
Если правился лишь код — достаточно `git pull`.

**Обязательно запусти на iPhone и проверь подключение.** Это единственная
защита от того, чтобы залить нерабочую сборку.

Не забудь **Team** у обоих таргетов — при пересоздании проекта он сбрасывается.
Ставить через вкладку **All**, иначе Release останется без него и Archive
упадёт.

## 3. Собери и загрузи

1. Вверху выбери **Any iOS Device (arm64)**
2. **Product → Archive**
3. В Organizer: **Distribute App → App Store Connect → Upload**

## 4. В App Store Connect

1. **Distribution** → рядом с «iOS App» нажми **+** → **iOS App**
2. Укажи номер версии (например `1.1`)
3. Заполни **What's New in This Version** — что изменилось
4. В блоке **Build** выбери новую сборку
5. Если у сборки написано **Missing Compliance** — нажми **Manage** и ответь
   про шифрование: стандартные алгоритмы, освобождение — да
6. **Save** → **Add for Review** → **Submit to App Review**

---

## Что переносится само

Не надо заполнять заново:

- политику конфиденциальности и Support URL
- описание, ключевые слова, категорию
- скриншоты (если интерфейс не менялся кардинально)
- App Privacy
- примечания для ревьюера

**Но ключ в Notes проверь.** Если срок действия истёк, ревьюер не сможет
подключиться, и это будет отказ.

## Обновление ядра sing-box

Отдельно и редко — когда выйдет новая версия ядра:

```bash
cd ~/Developer/KerimliRashad/zyng
rm -rf Frameworks .build
./build-core.sh
rm -rf Zyng.xcodeproj && ./setup.sh
```

Занимает 5–15 минут. После этого обязательно проверь подключение на устройстве:
libbox иногда меняет API между версиями, и связке может понадобиться правка.

Зафиксировать конкретную версию ядра:

```bash
# Версии закреплены в core/go.mod — правь их там и запускай ./build-core.sh
```

## Сколько это занимает

| Что | Время |
|---|---|
| Правка кода и проверка на телефоне | зависит от правки |
| Archive и загрузка | 10–15 минут |
| Обработка сборки у Apple | 15–30 минут |
| Заполнение версии и отправка | 5 минут |
| Проверка Apple | до 48 часов |

Обновления проверяют быстрее первой публикации — обычно меньше суток.
